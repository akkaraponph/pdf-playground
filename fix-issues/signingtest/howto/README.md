# PDF signing test guide

This guide explains how to run the `signingtest` use case against the local
`github.com/digitorus/pdfsign` checkout and verify the behavior from
[PR #169](https://github.com/digitorus/pdfsign/pull/169).

## What PR #169 changes

PR #169 fixes certification signatures so the PDF catalog contains the
required `/Perms /DocMDP` reference. The signature dictionary already carries
the DocMDP transform and permission value; the catalog reference is what makes
PDF readers apply the certification and display the document as certified.

The PR also covers these cases:

- Existing catalog `/Perms` entries are preserved while `/DocMDP` is merged.
- An already-certified document cannot receive a second certification
  signature; use an approval signature instead.
- A certification signature must be the first signature in the document.
- Malformed `/Perms`, signed fields, inherited field types, and field-tree
  cycles are rejected before writing.
- Copied PDF names and literal strings are escaped safely.

## Prerequisites

- Go 1.27 or newer.
- A PEM-encoded signing certificate and matching private key. Keep these
  outside Git and pass their paths explicitly.
- Optional: Poppler's `pdfsig` and `pdfinfo` commands.
- Optional: `qpdf` for inspecting the catalog and indirect objects.

The `signingtest/go.mod` file uses a local `replace` directive for
`github.com/digitorus/pdfsign`. Before testing PR #169, make sure that local
checkout is at the PR branch or commit, for example in a separate clone:

```sh
git -C /path/to/pdfsign status
git -C /path/to/pdfsign log -1 --oneline
```

Do not put private keys or PKCS#12 bundles in this repository.

## Run the signing test

From the repository root:

```sh
cd signingtest
go test ./...
go run ./cmd/generate-mock-pdf
go run ./cmd/sign-pdf \
  -input testdata/mock-signing-document.pdf \
  -output results/mock-signing-document-signed.pdf \
  -certificate /secure/path/signer.crt \
  -private-key /secure/path/signer.key \
  -chain /secure/path/chain.crt
```

Omit `-chain` when the certificate is self-signed or no intermediate/root
certificates need to be embedded. The command creates the output directory,
writes a certification signature, and performs the use-case verification.

## Verify the output

First check the PDF signature cryptographically:

```sh
pdfsig results/mock-signing-document-signed.pdf
pdfinfo results/mock-signing-document-signed.pdf
```

The `pdfsig` output should report a valid signature and the complete document
as signed. A local trust-store warning is separate from cryptographic
signature validity when using a private or test certificate.

To inspect the catalog entry added by PR #169:

```sh
qpdf --qdf --object-streams=disable \
  results/mock-signing-document-signed.pdf \
  /tmp/mock-signing-document-signed.qdf.pdf

rg -a -n "/Perms|/DocMDP|/TransformMethod|/P " \
  /tmp/mock-signing-document-signed.qdf.pdf
```

Confirm that:

1. The catalog contains `/Perms` with `/DocMDP N 0 R`.
2. Object `N 0 R` is the signature dictionary.
3. The signature dictionary contains `/TransformMethod /DocMDP`.
4. The transform parameters contain the intended `/P` permission value.
5. Existing `/Perms` entries, if present, remain in the rewritten dictionary.

## Negative checks

The certification signature must be first and unique. Use the first signed
output as a follow-up input and confirm that a second certification attempt is
rejected. A document that already contains a signed field must also be
rejected for certification.

For the complete edge-case suite, run the tests in the `pdfsign` checkout:

```sh
cd /path/to/pdfsign
go test ./sign -run 'Test(CreateCatalog|.*DocMDP.*)' -count=1
go test ./...
```

The PR description reports that build, vet, and tests are green; use the
actual checkout under test as the source of truth for the final result.

## Troubleshooting

### The Go verifier rejects a real certificate because it has no EKU

Some valid signing certificates do not include an Extended Key Usage
extension. The current verification policy may reject those certificates even
when `pdfsig` reports that the PDF signature itself is valid. Record both
results: the cryptographic signature check and the certificate-policy result.

### `/Perms` is missing

Check that the `signingtest` module is actually using the PR #169 checkout
shown by its `replace` directive. If the module points to another checkout,
the output may be generated by pre-PR code.

### A second certification fails

That is expected. PR #169 requires a certification signature to be the first
signature. Use an approval signature for a document that is already certified.
